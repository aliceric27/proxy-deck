# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ProxyDesk is a Windows desktop proxy client: it pulls SOCKS5 nodes from Mudfish and runs sing-box in TUN mode so only chosen apps/domains go through the proxy. Design decisions and verified findings live in `docs/PLAN.md` — read the relevant section before changing routing, DNS, or privilege behavior.

## Commands

```powershell
pwsh -File scripts/fetch-singbox.ps1          # required once: sidecar binary is not in git
cd apps/desktop; npm install; npm run tauri dev
npm run tauri build                           # NSIS installer in target/release/bundle/nsis/
cargo test -p proxy-core                      # set SINGBOX_BIN=<sidecar exe> to also run `sing-box check` on generated configs
cargo test -p proxy-core singbox::tests::mixed_group_is_logical_or_of_separate_matchers   # single test
cargo test --workspace                        # also regenerates apps/desktop/src/lib/bindings/*.ts (ts-rs)
cd apps/desktop; npx tsc --noEmit
```

The app manifest is `requireAdministrator` (TUN), so `tauri dev` and `cargo test -p proxydesk` need an elevated shell. Debug builds expose WebView2 DevTools on `PROXYDESK_CDP_PORT` (e.g. 9222) for Playwright `connectOverCDP` UI automation; release builds never do. While that port is open any local process can drive the elevated webview — set it only for automation runs.

## Architecture

- `crates/proxy-core` — no Tauri dependency. `model.rs` is the persisted `Profile` (serde, `#[serde(default)]` so old profiles keep loading — add new fields with defaults; bump `PROFILE_SCHEMA_VERSION` (3) and extend `Profile::migrate` for shape changes. Fields of older shapes stay readable as `legacy_*` fields — `#[serde(rename, default, skip_serializing)] #[ts(skip)]` — see **Profile file** below). Routing is an ordered list of custom `RuleGroup`s (each mixes app/domain/rule-set/IP matchers, any-of), then the fixed `GeoIpGroup` (countries of the destination IP), then `final`. Each of them has one `outbound`: `direct`, `reject` (block), `auto` or a node tag — a removed node falls back to `auto` (`Profile::effective_outbound`). Global mode has its own `global_outbound` (`auto` or a node). `singbox.rs::generate` turns a Profile into sing-box 1.14 JSON; `restart_fingerprint` is that config minus the live-switchable parts; `mudfish.rs` parses `https://mudfish.net/api/staticnodes`.
- **Selectors**: `Profile::selections()` is `Selections { mode, selectors }`, selector tag → the member it is switched to: `global` (members: `auto` + nodes), `final`, `geoip` (only while it has countries) and `group-<id>` of each enabled group (members: `direct`, `auto` + nodes). A group, GeoIP or `final` whose outbound is `reject` has no selector. The generator creates its selectors from this very list, so the config and the live switches cannot diverge. `reject` is a profile-only pseudo outbound (`TAG_REJECT`): the generator turns it into `"action": "reject"`; it must never appear as an outbound tag or selector member in the sing-box config.
- **Profile file**: `store::load_profile` runs at startup. `Profile::migrate` only converts files with `schema_version < 3`; a current-schema file is never converted again, and stray old keys in it are ignored and dropped by the next save. Before a migrated profile is saved, the original is copied to `profile.v<old>-backup.json` (never overwritten). The v2 → v3 migration keeps every route (the old default node S becomes the outbound of everything that followed it), with two things v3 cannot express: Global mode with a direct S becomes Direct mode (which is what it did), and a group that followed a direct S is a plain direct group now, so its `udp` policy stays in the file but is inert (direct groups get no UDP guard, QUIC block or FakeIP rule). A file that cannot be read or parsed has two outcomes (`LoadFailure::verdict`). **Moved aside** to the first free `profile.json.bad`, `.bad-2`, … (never over an earlier one): the defaults are used, nothing is written, and `load_profile` returns a notice (`AppState.notice` → `Snapshot.notice` → a warning in `App.tsx` `Banners` for the whole session). **Cannot even be moved** (typically another process holds it for the moment: a sharing violation): `load_profile` returns `Err`, so `setup` shows `fatal`'s dialog and the app does not start, with the original untouched — continuing on the defaults would let the first save overwrite a file that is most likely fine. `load_checked`/`load_or_default` (the node cache) set a file aside the same way but carry on with the defaults either way. A missing file is a first run: defaults, no notice.
- `apps/desktop/src-tauri/src/core.rs` — `CoreManager` is the sing-box state machine: start → check → spawn → health → apply selections → supervise, with a bounded auto-restart (backoff) after crashes and a generation counter so intentional stops never look like crashes. It has no Tauri dependency: process work goes through the `Launcher` trait (`SingBox` in production, a scripted fake in tests) and notifications through `CoreEvents` (`lib.rs` forwards them as `core-status` / batched `core-log` events and to the tray). The config reaches sing-box over stdin (`-c stdin`) and never touches the disk; the working dir `%ProgramData%\ProxyDesk\run` is created admin-only by `paths::secure`. The child sits in a Job Object (KILL_ON_JOB_CLOSE); an orphan sweep runs in the background at startup.
- **Single write path**: the frontend changes the profile only through `updateProfile` → `save_profile` (queued, in order). The backend persists, applies `Profile::selections()` (the choice of every selector, and the mode) to a running core through the Clash API, and returns whether a reconnect is still needed (`stale`, from `restart_fingerprint`). Selector switches rely on `interrupt_exist_connections`; only a mode switch closes all connections. Switches to a selector or member the running config lacks (group/node added after the start, or a selector that did not exist because its outbound was `reject`) are skipped — `stale` already asks for a reconnect. Only some changes stay live: GeoIP and final between direct and nodes (they touch no DNS), Global between `auto` and nodes, and a group between nodes. Changing the GeoIP countries or going to/from `reject` changes the config, and so does a group going between direct and proxied while it has domain/geosite conditions or its own UDP policy (its FakeIP DNS rules, QUIC block and UDP guard come or go). `start` runs `sing-box check` before stopping the running core, and `CoreManager::fail` never stops a running core, so an invalid profile or rejected config costs no connection.
- Types shared with the frontend derive `ts_rs::TS` + `#[ts(export)]`; `cargo test` writes them to `apps/desktop/src/lib/bindings/` (generated and committed — never edit by hand). `src/lib/ipc.ts` only wraps commands and events.
- Live traffic: `traffic.rs` polls the Clash API once per second, only while connected and the window is visible, and pushes a `traffic` event.

## Constraints verified on Windows (don't regress)

- sing-box hands SOCKS5 the IP, not the sniffed domain → proxied domains need FakeIP for remote resolution. A FakeIP destination routed to `direct` still works (the domain is restored and resolved locally). Domains only a proxied GeoIP or `final` catches are resolved locally, so the node gets just the IP.
- **The default DNS must stay real** (`dns.final` = `dns-local`): only the domains of proxied custom groups get FakeIP. GeoIP matches the destination IP and uses no `resolve` action, so a domain no group claimed has to arrive as the real IP it resolved to. Making the default DNS FakeIP would silently disable GeoIP. `dns-remote` goes through `auto`.
- Mudfish nodes are IPv4-only: an app choosing an AAAA answer gets EOF on proxied connections → `dns.ipv4_only` defaults on.
- Inside one sing-box rule, `process_name`/`process_path`/`process_path_regex`/`rule_set`/`network`/`port` are ANDed (only domain fields OR). A group's matchers must therefore be separate sub-rules under a logical `or` — never merge different matcher kinds into one rule object.
- Route order: sniff → hijack-dns → ProxyDesk's own exe direct → private IPs direct → `clash_mode` Direct / Global (Global → the `global` selector) → per custom group (its QUIC block and UDP guard only while it is proxied, then its rule) → GeoIP (one `rule_set` rule of the `geoip-<code>` sets; skipped without countries) → final. `route.final` is the `final` selector; a blocked final instead adds a catch-all reject rule after GeoIP and sets `route.final` to `direct`. Exceptions that must hold in every mode go before the mode switches; a group's QUIC block sits right before its rule so a higher-priority direct group still wins.
- In DNS rules only `geosite:` sets are used; geoip/acl sets contain IP CIDRs, which 1.14 rejects next to `query_type`.
- Windows `process_name` matches the full file name (`curl.exe`); the UI auto-appends `.exe`. Paths and directories become case-insensitive `process_path_regex` (`/` accepted as separator).
- sing-box's `cache_file` restores selectors and the Clash mode under its `cache_id`, overriding `default`/`default_mode`; a fresh `cache_id` per start makes the profile win (FakeIP mappings are not keyed by it and survive). Selections are applied again after every health check (auto-restarts reuse the same plan).
- sing-box only switches to Clash modes that some rule mentions (plus `default_mode`), and answers 204 even when it ignores the request. The generator keeps all three modes mentioned (a no-op DNS rule names `Rule`); `ClashClient::set_mode` reads the mode back.
- WARP nodes (`ProxyNode.wireguard`) are WireGuard **endpoints** in sing-box, not outbounds; their private keys live in Credential Manager under `node-<tag>` and are passed to `generate` via `GenerateOptions.wireguard_keys`. `auto` excludes WARP while any Mudfish node exists (WARP's local edge would always win on latency). Removing a WARP node deregisters the device with Cloudflare and deletes its secret.
- Mudfish SOCKS credentials are the account ID/password: keep them in Windows Credential Manager only, never in `profile.json`, on disk or in logs. `.env.local` (gitignored) is for local scripts.
