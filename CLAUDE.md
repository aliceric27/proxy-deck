# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ProxyDesk is a Windows desktop proxy client: it pulls SOCKS5 nodes from Mudfish (plus generated Cloudflare WARP nodes and hand-added HTTP/SOCKS5 proxies) and runs sing-box in TUN mode so only chosen apps/domains go through the proxy. Design decisions and verified findings live in `docs/PLAN.md` — read the relevant section before changing routing, DNS, or privilege behavior.

## Commands

```powershell
pwsh -File scripts/fetch-singbox.ps1          # required once: sidecar binary is not in git
cd apps/desktop; npm install; npm run tauri dev
npm run tauri build                           # NSIS installer in target/release/bundle/nsis/
cargo test -p proxy-core                      # set SINGBOX_BIN=<sidecar exe> to also run `sing-box check` on generated configs
cargo test -p proxy-core singbox::tests::mixed_group_is_logical_or_of_separate_matchers   # single test
cargo test --workspace                        # also regenerates apps/desktop/src/lib/bindings/*.ts (ts-rs)
cd apps/desktop; npx tsc --noEmit
```

GitHub (`aliceric27/proxy-deck`): `.github/workflows/ci.yml` runs on `windows-latest` — fetch sidecar, `npm ci` + `npm run build` (the Tauri crate needs `../dist`), clippy `-D warnings`, `cargo test --workspace` with `SINGBOX_BIN`, and fails if the regenerated bindings differ from the committed ones. `release.yml` runs on a `v*` tag: the tag must equal `tauri.conf.json`'s version, and it builds the NSIS installer and creates a **draft** release with it and `SHA256SUMS.txt`. A release bumps the version in `Cargo.toml` (workspace), `Cargo.lock`, `package.json`, `package-lock.json` and `tauri.conf.json`. `README.md` is English, `README.zh-TW.md` Traditional Chinese — keep both in step.

The app manifest is `requireAdministrator` (TUN), so `tauri dev` and `cargo test -p proxydesk` need an elevated shell. Debug builds expose WebView2 DevTools on `PROXYDESK_CDP_PORT` (e.g. 9222) for Playwright `connectOverCDP` UI automation; release builds never do. While that port is open any local process can drive the elevated webview — set it only for automation runs.

## Architecture

- `crates/proxy-core` — no Tauri dependency. `model.rs` is the persisted `Profile` (serde, `#[serde(default)]` so old profiles keep loading — add new fields with defaults; bump `PROFILE_SCHEMA_VERSION` (3) and extend `Profile::migrate` for shape changes. Fields of older shapes stay readable as `legacy_*` fields — `#[serde(rename, default, skip_serializing)] #[ts(skip)]` — see **Profile file** below). Routing is an ordered list of custom `RuleGroup`s (each mixes app/domain/rule-set/IP matchers; `match_mode` is `any` (OR, the default) or `all` (AND across the populated kinds; values within one kind still OR)), then the fixed `GeoIpGroup` (countries of the destination IP), then `final`. Each of them has one `outbound`: `direct`, `reject` (block), `auto` or a node tag — a removed node falls back to `auto` (`Profile::effective_outbound`). Global mode has its own `global_outbound` (`auto` or a node). `singbox.rs::generate` turns a Profile into sing-box 1.14 JSON; `restart_fingerprint` is that config minus the live-switchable parts (secrets are placeholders there, so an account change never marks the profile stale); `mudfish.rs` parses `https://mudfish.net/api/staticnodes`; `custom.rs` validates hand-added nodes and parses pasted proxy links. `import.rs` reads pasted or uploaded JSON (ProxyDesk groups, Karing diversion rules and presets, sing-box rule-set sources and config `route.rules`) into groups for the import dialog, which adds them through `save_profile`; whatever a group cannot express is dropped and listed in the notes, never silently changed. A sing-box rule ANDs its kinds while its domain and IP fields OR, so such a rule becomes an AND group, split into app+domain and app+IP when it has both.
- **Node kinds** (`ProxyNode`): Mudfish (neither `wireguard` nor `custom`), WARP (`wireguard`), hand-added (`custom: { protocol: http | socks5 }`, tag `custom-<8 hex>`). `auto` (urltest) picks from the first non-empty kind in the order Mudfish → WARP → hand-added (`singbox::auto_members`): the other kinds are only chosen explicitly (WARP's nearby edge always wins on latency; hand-added proxies are often TCP-only, so `auto` landing on one would break UDP — user decision).
- **Selectors**: `Profile::selections()` is `Selections { mode, selectors }`, selector tag → the member it is switched to: `global` (members: `auto` + nodes), `final`, `geoip` (only while it has countries) and `group-<id>` of each enabled group (members: `direct`, `auto` + nodes). A group, GeoIP or `final` whose outbound is `reject` has no selector. The generator creates its selectors from this very list, so the config and the live switches cannot diverge. `reject` is a profile-only pseudo outbound (`TAG_REJECT`): the generator turns it into `"action": "reject"`; it must never appear as an outbound tag or selector member in the sing-box config.
- **Profile file**: `store::load_profile` runs at startup. `Profile::migrate` only converts files with `schema_version < 3`; a current-schema file is never converted again, and stray old keys in it are ignored and dropped by the next save. Before a migrated profile is saved, the original is copied to `profile.v<old>-backup.json` (never overwritten). The v2 → v3 migration keeps every route (the old default node S becomes the outbound of everything that followed it), with two things v3 cannot express: Global mode with a direct S becomes Direct mode (which is what it did), and a group that followed a direct S is a plain direct group now, so its `udp` policy stays in the file but is inert (direct groups get no UDP guard, QUIC block or FakeIP rule). A file that cannot be read or parsed has two outcomes (`LoadFailure::verdict`). **Moved aside** to the first free `profile.json.bad`, `.bad-2`, … (never over an earlier one): the defaults are used, nothing is written, and `load_profile` returns a notice (`AppState.notice` → `Snapshot.notice` → a warning in `App.tsx` `Banners` for the whole session). **Cannot even be moved** (typically another process holds it for the moment: a sharing violation): `load_profile` returns `Err`, so `setup` shows `fatal`'s dialog and the app does not start, with the original untouched — continuing on the defaults would let the first save overwrite a file that is most likely fine. `load_checked`/`load_or_default` (the node cache) set a file aside the same way but carry on with the defaults either way. A missing file is a first run: defaults, no notice.
- `apps/desktop/src-tauri/src/core.rs` — `CoreManager` is the sing-box state machine: start → check → spawn → health → apply selections → supervise, with a bounded auto-restart (backoff) after crashes and a generation counter so intentional stops never look like crashes. It has no Tauri dependency: process work goes through the `Launcher` trait (`SingBox` in production, a scripted fake in tests) and notifications through `CoreEvents` (`lib.rs` forwards them as `core-status` / batched `core-log` events and to the tray). The config reaches sing-box over stdin (`-c stdin`) and never touches the disk; the working dir `%ProgramData%\ProxyDesk\run` is created admin-only by `paths::secure`. The child sits in a Job Object (KILL_ON_JOB_CLOSE); an orphan sweep runs in the background at startup.
- **Single write path**: the frontend changes the profile only through `updateProfile` → `save_profile` (queued, in order). The backend persists, applies `Profile::selections()` (the choice of every selector, and the mode) to a running core through the Clash API, and returns whether a reconnect is still needed (`stale`, from `restart_fingerprint`). A selector switch relies on `interrupt_exist_connections` and, as a deterministic backstop, also closes the connections still on that selector's *previous* member (`Launcher::interrupt` → `ClashClient::close_switched_connections`, which matches the chain element just before the selector so a freshly re-dialed connection on the new member is left alone; best-effort, skipped when the live state is unknown after a failed apply — the resync then re-sends unchanged selectors, which are core-side no-ops — or when a mode switch's `CloseAll` already closed everything); only a mode switch closes all connections. Switches to a selector or member the running config lacks (group/node added after the start, or a selector that did not exist because its outbound was `reject`) are skipped — `stale` already asks for a reconnect. Only some changes stay live: GeoIP and final between direct and nodes (they touch no DNS), Global between `auto` and nodes, and a group between nodes. Changing the GeoIP countries or going to/from `reject` changes the config, and so does switching a group's `match_mode` and a group going between direct and proxied while it has domain/geosite conditions or its own UDP policy (its FakeIP DNS rules, QUIC block and UDP guard come or go). `start` runs `sing-box check` before stopping the running core, and `CoreManager::fail` never stops a running core, so an invalid profile or rejected config costs no connection.
- **Mudfish node list**: `nodes.rs` `NodeSource` (`AppState.node_list`, behind `get_nodes`) fetches on the first load of each run — the frontend's `loadNodes` makes it right after the first snapshot — and then reuses that run's list for 6 h unless forced; a load that arrives during a fetch waits for it. Offline, the saved `mudfish-nodes.json` comes back with `NodeList.error` set (retried after 60 s). Added Mudfish nodes are copies (`server`, `name`, `country`), so `loadNodes` brings them in line with every list fetched this run — never with the saved fallback, which may be older than the nodes — through `updateProfile`, keeping `udp`.
- Types shared with the frontend derive `ts_rs::TS` + `#[ts(export)]`; `cargo test` writes them to `apps/desktop/src/lib/bindings/` (generated and committed — never edit by hand). `src/lib/ipc.ts` only wraps commands and events.
- Live traffic: `traffic.rs` polls the Clash API once per second whenever the core has one — also while the window is hidden in the tray — feeds every sample to the traffic history, and pushes a `traffic` event only while the window is visible.
- **Traffic history** (`stats.rs`, page 流量統計): one `TrafficSession` per connection session — opened by the first `Running` after a `Starting` (or after a `Reconnecting` with no session open), closed by `Stopped` / `Error` / the next `Starting`, and ended at its last sample. A session a `Starting` replaced waits in `Recorder.replaced` for the start's outcome: `reconnected` on `Running`, `error` / `stopped` otherwise. An auto-restart after a crash (`Reconnecting` → `Running`) stays in the session and the new core's counters are added on; only `Reconnecting` resets the counter baseline, because `launch` exposes the new core's Clash client before it reports `Running` and the poller may sample it in between. `TauriEvents::status` feeds `TrafficStats::on_status` synchronously under the core's lock, so status changes are in order; each poll carries the `epoch` it started under and is dropped if a status change came in meanwhile, so no bytes cross sessions. Totals are sing-box's counters (exact); the split by exit (`chains[0]`) and by program adds up per-connection growth between samples, so bytes of a connection that closed between samples are unattributed (shown as 「其他」). `history()` lists saved, closed-but-unsaved and running sessions, so nothing vanishes between a status change and the next `persist`; the page reloads it on status changes and polls `traffic_current` every 5 s. Closed sessions → `traffic-history.json` (newest 200, compact JSON via `store::save_compact`, retried while a write fails); the running one → `traffic-current.json` once a minute, removed only once its session is in the history file, and filed as `interrupted` at the next start. A session with zero bytes is not kept. Only byte counts, times, node names and lower-cased program file names are stored — no hosts, IPs or paths. `quit` / `RunEvent::Exit` call `persist(true)` after stopping the core.

## Constraints verified on Windows (don't regress)

- sing-box hands SOCKS5 the IP, not the sniffed domain → proxied domains need FakeIP for remote resolution. A FakeIP destination routed to `direct` still works (the domain is restored and resolved locally). Domains only a proxied GeoIP or `final` catches are resolved locally, so the node gets just the IP.
- **The default DNS must stay real** (`dns.final` = `dns-local`): only the domains of proxied custom groups get FakeIP. GeoIP matches the destination IP and uses no `resolve` action, so a domain no group claimed has to arrive as the real IP it resolved to. Making the default DNS FakeIP would silently disable GeoIP. `dns-remote` goes through `auto`.
- Mudfish nodes are IPv4-only: an app choosing an AAAA answer gets EOF on proxied connections → `dns.ipv4_only` defaults on.
- Inside one sing-box rule, `process_name`/`process_path`/`process_path_regex`/`rule_set`/`network`/`port` are ANDed (only domain fields OR). A group's matchers must therefore be separate sub-rules — never merge different matcher kinds into one rule object. OR groups (`match_mode: any`) put every field sub-rule under a logical `or` (`group_matchers`, the historical flat shape, kept byte-for-byte). AND groups (`all`) put one sub-rule per *user-facing kind* (app / IP / rule set / domain) under a logical `and`, where the app kind's own `process_name` + `process_path_regex` are first OR-ed together (`group_kind_matchers`) — so the kinds AND while a kind's values, the app names/paths especially, still match any-of.
- A *multi-kind* AND group (`is_multi_kind_and`: `match_mode: all` with 2+ populated kinds — a one-kind AND is identical to OR, so it is treated as OR here) gets no FakeIP DNS rule and no QUIC block. A DNS rule cannot see which app is asking, so FakeIP keyed on such a group's domain would hand every app a fake IP (GeoIP then has no real IP to match) while the route rule still needs the app too; the QUIC block names the domain alone for the same reason. The domain resolves for real and the route rule matches the SNI/Host that sniffing finds.
- Route order: sniff → hijack-dns → ProxyDesk's own exe direct → private IPs direct → `clash_mode` Direct / Global (Global → the `global` selector) → per custom group (its QUIC block only while it is proxied, matches by OR and its UDP follows the group; its UDP guard only while it is proxied; then its rule) → GeoIP (one `rule_set` rule of the `geoip-<code>` sets; skipped without countries) → final. `route.final` is the `final` selector; a blocked final instead adds a catch-all reject rule after GeoIP and sets `route.final` to `direct`. Exceptions that must hold in every mode go before the mode switches; a group's QUIC block sits right before its rule so a higher-priority direct group still wins.
- In DNS rules only `geosite:` sets are used; geoip/acl sets contain IP CIDRs, which 1.14 rejects next to `query_type`.
- Windows `process_name` matches the full file name (`curl.exe`); the UI auto-appends `.exe`. Paths and directories become case-insensitive `process_path_regex` (`/` accepted as separator).
- sing-box's `cache_file` restores selectors and the Clash mode under its `cache_id`, overriding `default`/`default_mode`; a fresh `cache_id` per start makes the profile win (FakeIP mappings are not keyed by it and survive). Selections are applied again after every health check (auto-restarts reuse the same plan).
- sing-box only switches to Clash modes that some rule mentions (plus `default_mode`), and answers 204 even when it ignores the request. The generator keeps all three modes mentioned (a no-op DNS rule names `Rule`); `ClashClient::set_mode` reads the mode back.
- WARP nodes (`ProxyNode.wireguard`) are WireGuard **endpoints** in sing-box, not outbounds; their private keys live in Credential Manager under `node-<tag>` and are passed to `generate` via `GenerateOptions.wireguard_keys`. `auto` excludes WARP while any Mudfish node exists (WARP's local edge would always win on latency). Removing a WARP node deregisters the device with Cloudflare and deletes its secret.
- Hand-added nodes (`ProxyNode.custom`) keep their username/password in Credential Manager under `node-<tag>` (`credentials::load_proxy_auth`), never in `profile.json`, and reach `generate` via `GenerateOptions.proxy_auth`. Every such node needs an entry (an empty username = no authentication), else `MissingProxyAuth`. Unlike WARP, the profile is saved **before** the account: `custom_node_build` only validates and returns the node, the frontend saves it through `save_profile`, then `custom_node_store_auth` writes the account only if the profile now holds exactly that node (`CustomNodeInput::account_for_saved`) — so a failed save never leaves an account that disagrees with the profile's server, and no account is written for an unsaved node. `save_profile` deletes the account when the node is removed. The edit dialog gets the username back (`custom_node_username`; `None` = no readable account, and saving waits until it is known), never the password (`null` keeps it; a pasted link's empty password clears it).
- sing-box's HTTP outbound has no `network` option (unknown field → config rejected): HTTP nodes are TCP-only (`udp` false) and only SOCKS5 nodes get `"network": "tcp"`.
- Mudfish SOCKS credentials are the account ID/password: keep them in Windows Credential Manager only, never in `profile.json`, on disk or in logs. `.env.local` (gitignored) is for local scripts.
- The account test (`verify_account`, `mudfish_probe.rs`) is a SOCKS5 username/password handshake only — no CONNECT, so no credit is spent — against up to 6 nodes in parallel. Mudfish answers a wrong password and a valid account with no credit identically (RFC 1929 status 0x02, then it closes the socket), so the result is only usable / unusable / unreachable: never tell the user which of password and credit is wrong.
